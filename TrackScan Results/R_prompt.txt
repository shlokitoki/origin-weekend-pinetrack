PROCESSING (per recording)
1. Meters: x = lon * 111320 * cos(34.03 deg), y = lat * 110950.
2. Resample the accelerometer to a uniform grid with step = median time step (approx()). fs = 1/step.
3. Vertical vibration: gravity vector G = each axis low-passed with a 2nd-order Butterworth at 0.3 Hz, zero-phase (signal::filtfilt). vertical = (A · G) / |G| (works even if the phone is tilted). Then band-pass vertical at 1–30 Hz (4th-order Butterworth, zero-phase; normalize cutoffs by fs/2). Remove the mean before filtering.
4. Split into 1-second windows. For each: window center time and RMS of the band-passed vertical signal.
5. GPS: drop fixes with Horizontal Accuracy > 40 m. Linearly interpolate lat/lon to each window center. Drop windows whose nearest GPS fix is more than 4 s away.
6. Snap to the track: project each window's point onto every segment of eline_shape (vectorized), keep the closest. chainage s = cumulative length up to that segment + fraction along it. Drop windows more than 60 m from the track.
7. Speed: use "Velocity (m/s)" (interpolated) where it is >= 0; otherwise |Δs/Δt| smoothed with a centered 5-window rolling median.
8. BRAKING / ACCELERATING DETECTION: smooth speed (fill gaps up to 5 windows, then centered 3-window rolling mean). long_acc = derivative of smoothed speed over time (m/s^2). "Stopped" = speed < 1 m/s. For each window compute seconds until the next stopped window and seconds since the last one. Phase:
   - "braking" if long_acc < -0.3 OR within 10 s before a stop
   - "accelerating" if long_acc > +0.3 OR within 10 s after a stop (braking wins if both)
   - otherwise "cruise"
9. Keep windows with speed >= 3 m/s. Record direction per recording (sign of the slope of s vs time: increasing = westbound).

ACROSS RECORDINGS
10. Rides: sort recordings by START epoch; a new ride starts when the gap to the previous START is > 180 s. Label rides "Ride k · HH:MM · WB/EB" in America/Los_Angeles time.
11. Print the phase share of all moving windows, then keep ONLY cruise windows for everything below.
12. Speed adjustment: fit lm(log(rms) ~ log(speed)) on all cruise windows pooled; slope b clipped to [0, 2]. adj = rms / speed^b.
13. Per-recording normalization: score = adj / median(adj of that recording) (so 1 = a typical stretch for that phone).
14. 25 m bins: bin = floor(s/25). For each recording × bin take the max score. A recording's bin is "hot" if that value >= the recording's 90th percentile of window scores.
15. Per bin: recordings covering it, median score across recordings, hot fraction. Hotspot bins: covered by >= ceiling(0.5 × number of recordings) recordings, hot fraction >= 0.5, median score >= 1.5. Merge adjacent hotspot bins into segments, then merge segments whose gap is <= 75 m into zones.
16. Per zone: severity = max median bin score; rides_rough = rides where ANY phone was hot in ANY bin of the zone; rides_covering; both_directions (rough on at least one WB and one EB ride); nearest station and distance to it (by chainage); "between Station A → Station B"; cross street = nearest bus stop name within 150 m (else NA); station_zone flag if within 150 m of a station; Google Maps link https://www.google.com/maps?q=LAT,LON at the zone's peak. Keep zones with rides_rough >= 3. Rank by severity × (rides_rough / rides_covering) × (1.25 if both directions).
17. Chance test: using only bins covered by all rides (cruise data), take each ride's hot/not-hot sequence, circularly shift it by a random offset (set.seed(0)), 2000 times; count bins hot on ALL rides each time. Report observed count vs mean and max of the shuffles.
